# Open Vox Keys beta.2 audit — 2026-09-23

Scope: the public Windows application, optional reference gateway/adapters,
installer, published artifacts and setup documentation at
`3c55eb2ffdf35a628bbbbc731152ffe8d3991da0` (`v0.3.0-beta.2`).
The fixes below form the beta.3 candidate. Final release/CI evidence is linked
from the release notes; a candidate is not a deployed fix.

## Method

Three separate AI reviewers examined security/privacy, Windows behavior, and ASR
protocol/completeness. A coordinator examined packaging, installation, release
consistency and public onboarding. Reviewers first inspected the baseline, then
reproduced defects using isolated files or fake upstream services. They reviewed
one another's fixes in a second round. This provides separate review contexts,
not organizational independence or an external security certification.

No synthetic modifier keys, production denial-of-service attempts, paid model
calls, or new ASR benchmarks were part of finding reproduction. Installer fault
reproduction used temporary Windows directories. Destructive lifecycle tests
run only in a disposable CI runner and refuse an existing installation.

## Confirmed findings and corrections

| ID | Priority | Baseline defect and trigger | Correction / regression evidence |
|---|---|---|---|
| A1 | High | Upstream ends its stream after only a prefix, before client stop; gateway could accept that prefix with the entire audio sample count. | Final stream eligibility requires client stop and upload EOF. Fake upstream regression rejects premature completion. |
| A2 | High | VAD-negative section was marked successfully transcribed without ASR, dropping quiet/missed speech. | Every nonzero section reaches batch ASR. Two-section regression preserves the second VAD-negative section. Only digital-zero audio skips ASR. |
| A3 | Medium | Start a session and stop sending audio: sole gateway slot could remain occupied indefinitely. | Configurable 15-second capture idle and 660-second wall-clock limits; tests confirm error and slot release. |
| A4 | Medium | Batch completion timeout bypassed an already complete streaming result. | Select the complete stream when final batch wait expires. Malformed response types also enter fallback. |
| S1 | Medium | Gateway accepted browser-origin WebSockets; a cross-origin page could conditionally occupy its slot. | Reject Origin headers before session handling; fake-service regression. Browser network protections affect real exploitability. |
| S2 | Medium | Loopback adapter accepted cross-origin text/plain POST /warm, changing model residency. | Reject browser Origin and require endpoint-specific content types; mocked-loader tests, no real GPU allocation. |
| S3 | Medium | Pinned aiohttp 3.13.2 falls in published denial-of-service advisory ranges. | Pin 3.14.3; all backend tests pass with isolated updated dependencies. See dependency evidence. |

it is not a CVSS assessment. Findings were not accepted by agent vote alone:
control-flow evidence and reproducible triggers take precedence.

## Security, artifacts and dependencies

A scoped scan of public main/tag history (85 unique blobs at baseline) and the
actual downloaded public ZIP (294 entries) found no matches for the examined
credential patterns, private infrastructure identifiers or agent-memory paths.
Local historical branches and local development binaries were excluded from
public exposure claims. Pattern scans cannot prove absence of every secret.

[Dependency evidence](audit-2026-09-23-dependencies.json) records exact versions,
primary upstream advisories, advisory-query results and limits. Seven locked
NuGet packages and ten resolved packages in the isolated updated Python stack
returned no advisory records at query time. Bundled .NET/WindowsDesktop 10.0.12
matched Microsoft's latest release metadata at audit time. Redistributed license
texts were inspected; no obvious omitted notice or bundled model weight was found.
This is not a legal opinion or a guarantee against unknown vulnerabilities.

## Validation and boundaries

The Windows Release build, client selftests and eleven loopback protocol cases
passed. Backend tests increased from thirteen to twenty-two and passed in both
the existing test environment and the isolated aiohttp 3.14.3 environment.
Final CI additionally covers installer payload verification, normal installation,
autostart on/off, graphical-uninstaller registration, failed upgrade/removal,
corrupt-settings preflight, uninstall and personal-data retention.

Remaining limitations:
- No fresh Windows reboot acceptance, real hardware-unplug test, or comprehensive
  application/elevation/accessibility compatibility matrix was performed.
- Focus/input protection polls every 25 ms and cannot identify all changes inside
  browser/custom native controls sharing an HWND.
- Nonzero VAD-negative audio now reaches ASR. This prevents deliberate omission
  but increases work on noise and can expose model hallucinations. Protocol tests
  do not establish WER or acoustic cut quality.
- Cold fallback latency and worst-case gateway/client deadline overhead remain
  practical limits; a complete fallback can still time out.
- The comparison recorder uses Windows default input, independently of the
  dictation microphone selection; this is now documented.
- Installer visual/high-DPI redesign remains explicitly deferred in issue #12.
- Unsigned Windows x64 beta, external ASR services and model licenses required.
- No power-loss guarantee: reported file/registry errors are rolled back where
  possible; forcibly terminating Windows/installer during a transaction can
  require manual recovery of the retained backup.

## Repeatable release audit

For later releases, record the exact baseline commit and downloaded asset hashes;
review the five areas above in separate contexts; reproduce findings without
production disruption; add targeted regressions; have a different reviewer
inspect fixes; build and run lifecycle tests from the exact release commit;
download the published assets again and compare them with the CI artifacts.
List untested claims and deployment state explicitly. Passing a build alone
is not a full audit, and a source push alone is not a delivered Windows release.
